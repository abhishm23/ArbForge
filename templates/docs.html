ArbForge Documentation

ArbForge is a low-latency quantitative orderbook depth scanner and deterministic triangular arbitrage cycle engine built in pure Python 3.11+. It models spot cryptocurrency conversion as a directed graph, computes compound taker fees, evaluates Level-1 depth volume bottlenecks, and streams real-time telemetry to an institutional financial terminal dashboard.

Core Design Principles

Zero ML / Zero LLMs: All pricing and cycle calculations are strictly deterministic and mathematical.
Spread Realism: Orders never cross at mid-prices. Purchases transact at Ask; liquidations transact at Bid.
Level-1 Volume Capping: Yields are coupled with backward-propagated resting depth to evaluate actual executable dollar volume.

Monitored Universe & Canonical Cycles

The engine actively polls 7 core high-liquidity trading pairs from Binance Public Market Data REST endpoints without API keys:

  • BTCUSDT, ETHUSDT, ETHBTC
  • SOLUSDT, SOLBTC
  • BNBUSDT, BNBBTC

2. Reverse ETH: USDT -> ETH -> BTC -> USDT (Buy ETH @ Ask -> Sell ETH @ Bid -> Sell BTC @ Bid)

5. Forward BNB: USDT -> BTC -> BNB -> USDT (Buy BTC @ Ask -> Buy BNB @ Ask -> Sell BNB @ Bid)
6. Reverse BNB: USDT -> BNB -> BTC -> USDT (Buy BNB @ Ask -> Sell BNB @ Bid -> Sell BTC @ Bid)

Atomic Snapshot Reference Swap Pattern

In high-frequency quantitative systems, lock contention between rapid background network updates and algorithmic reader threads degrades latency. ArbForge implements the Atomic Snapshot Reference Swap pattern in arbforge/store.py:

  • Writers copy the current dictionary, apply new validated tickers, and execute an atomic pointer assignment (self._tickers = new_map) under an asyncio.Lock.
  • Readers read self._tickers completely lock-free in $O(1)$ time, guaranteeing that no reader ever blocks the network poller or observes a partially updated orderbook.

Arbitrage Mathematics & Formulation

Consider 3 sequential asset conversions starting and ending with asset $A$ (e.g. $USDT$): $$A \xrightarrow{\text{Leg 1}} B \xrightarrow{\text{Leg 2}} C \xrightarrow{\text{Leg 3}} A$$

1. DIRECTIONAL EXECUTION RULES
• Buying Base with Quote (Quote -> Base): Executes at Ask price
  Q_base = (Q_quote / Ask_price) * (1 - taker_fee)

• Selling Base for Quote (Base -> Quote): Executes at Bid price
  Q_quote = (Q_base * Bid_price) * (1 - taker_fee)
2. YIELD EQUATIONS
Gross Rate Multiplier = R_1 * R_2 * R_3
Gross Yield (%) = (Gross Multiplier - 1.0) * 100.0

Net Rate Multiplier = R_1(1 - f_1) * R_2(1 - f_2) * R_3(1 - f_3)
Net Yield (%) = (Net Multiplier - 1.0) * 100.0
3. SYNTHETIC VS DIRECT DISCREPANCY
For Forward Triangle (USDT -> BTC -> ALT -> USDT):
Synthetic Cross-Rate = Ask(ALTBTC) * Ask(BTCUSDT)
Direct Market Rate = Bid(ALTUSDT)
Discrepancy (%) = ((Direct Rate - Synthetic Rate) / Synthetic Rate) * 100.0

Level-1 Depth Bottlenecks & Sizing

A theoretical $+0.50\%$ yield is meaningless if the resting top-of-book depth is only $\$10$. ArbForge computes the exact backward-propagated maximum volume $V_{max}$ without walking beyond Level-1:

BACKWARD PROPAGATION ALGORITHM
Let Cap_1 be available depth on Leg 1 (in quote currency)
Let Cap_2 be available depth on Leg 2 (in asset 1 units)
Let Cap_3 be available depth on Leg 3 (in asset 2 units)

Limit_0 = Cap_1
Limit_1 = Cap_2 / r_1
Limit_2 = Cap_3 / (r_1 * r_2)

V_max (Max Executable Capital) = min(Limit_0, Limit_1, Limit_2)
Expected Net Profit (USDT) = V_max * (Net Yield % / 100.0)

Troubleshooting & FAQ

Port 8000 already in use (Errno 10048) ▾
Cause: A previous instance of ArbForge or another server is still bound to port 8000.
Solution: The updated launch.bat script now automatically scans for and terminates any process listening on port 8000 before starting. You can also manually free it in PowerShell: 
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
Why are net yields negative under normal conditions? ▾
Cause: In highly liquid crypto markets, triangular arbitrage discrepancies are typically small (1-4 bps). Standard taker fees (10 bps per leg = ~30 bps roundtrip) exceed the bid/ask disparity.
Solution: Profitable opportunities emerge during high volatility bursts or for VIP market makers with maker rebates or 0-fee promotions. Use the Taker Fee Slider in the simulator or UI to test lower fee tiers (e.g. BNB 7.5 bps or zero-fee VIP tiers).
HTTP 429 / 418 Rate Limit handling ▾
Cause: Binance enforces request weight rate limits (1200 weight/min).
Solution: ArbForge uses compact zero-whitespace parameter serialization (symbols=["BTCUSDT",...]) which consumes only 4-8 weight per request. The poller also tracks x-mbx-used-weight-1m and implements automatic exponential backoff on HTTP 429 responses.
